## 1. 프로젝트 개요

### 목적

Money Flow는 개인 및 가구의 월간 자금 흐름을 시각적으로 작성하고 관리하는 웹 애플리케이션이다.

급여 등 수입이 어느 계좌로 들어와 모이고, 다시 어떤 계좌나 카드로 이동하며, 최종적으로 어떤 명목으로 지출되는지 하나의 다이어그램으로 표현한다.

기존 구글 슬라이드로 작성하던 자금 흐름도를 대체하는 것이 첫 번째 목표다.

### 핵심 원칙

- 구글 슬라이드처럼 자유롭게 배치하고 편집할 수 있어야 한다.
- 계좌 간 자금 이동 경로를 직관적으로 파악할 수 있어야 한다.
- 연결선 두께로 금액 규모를 비교할 수 있어야 한다.
- 고정 금액과 최소·최대 예상 금액을 모두 표현한다.
- 금융사 브랜드 컬러를 활용한다.
- 사용자별 자금 사용 영역을 그룹으로 구분한다.
- 데이터와 레이아웃을 저장하고 공유할 수 있어야 한다.
- 브라우저에서 독립적으로 동작한다.
- 로그인과 백엔드는 초기 범위에서 제외한다.

### 구현하지 않을 기능

- 은행 및 카드사 API 연동
- 실제 거래 내역 자동 수집
- 가계부 및 소비 통계
- 예산 초과 알림
- 다중 사용자 실시간 협업
- 클라우드 계정 동기화
- AI 기반 지출 분석
- 금융사 로고 표시
- 다국어 UI (UI 언어는 한국어 하나만 제공한다)

### 2.2 보조 라이브러리

구현자가 임의로 고르지 않도록 용도별 선택을 정해 둔다.

| 용도             | 선택                              | 비고                                                     |
| ---------------- | --------------------------------- | -------------------------------------------------------- |
| 스키마 검증      | Zod                               | JSON 가져오기, 공유 데이터, 저장 데이터 복원에 공통 사용 |
| IndexedDB 접근   | `idb`                             | Promise 기반 래퍼                                        |
| Undo / Redo      | `zundo`                           | Zustand 이력 미들웨어                                    |
| 공유 데이터 압축 | 브라우저 기본 `CompressionStream` | 별도 의존성 없음                                         |
| 이미지 내보내기  | 직접 구현                         | 11장 참고, 별도 의존성 없음                              |
| ID 생성          | `crypto.randomUUID()`             | 별도 의존성 없음                                         |
| 라우터           | 사용하지 않음                     | 공유 화면은 URL 해시로 구분                              |

`CompressionStream`은 구현 시점에 대상 브라우저의 지원 범위를 공식 문서로 확인한다.
지원 범위가 부족하면 대체 라이브러리 도입을 PR에서 제안한다.

위 표에 없는 라이브러리는 기존 기능으로 해결할 수 없는 경우에만 추가하고, 추가 이유를 PR에 적는다.

별도 백엔드 서비스는 도입하지 않는다.

### 2.3 개발 환경

- Node.js: 현행 LTS
- 패키지 매니저: pnpm
- 포매터: Prettier. `templates/prettier/prettier.config.mjs`를 프로젝트 루트로 복사해 사용한다.
- 린터: ESLint (TypeScript, React 규칙)
- CI: PR마다 타입 검사, 린트, 단위 테스트, 빌드, Playwright 스모크 테스트를 실행한다.

### 2.4 브랜치 전략

| 브랜치 | 역할                                                                       | 병합 방식                     |
| ------ | -------------------------------------------------------------------------- | ----------------------------- |
| `dev`  | 기본 브랜치. 기능 브랜치는 `dev`에서 분기하고 PR의 기준 브랜치로 사용한다. | 기능 브랜치 PR은 squash merge |
| `main` | Vercel 프로덕션 배포 브랜치. `dev`에서만 병합한다.                         | merge commit                  |

`main`에서 직접 수정한 내용이 생기면 `main`에서 `dev`로 merge commit으로 되돌려 병합한다.

브랜치 룰셋은 `.github/rulesets/`의 JSON으로 관리한다.

| 규칙                     | `dev`         | `main` |
| ------------------------ | ------------- | ------ |
| 브랜치 삭제 금지         | 적용          | 적용   |
| 강제 푸시 금지           | 적용          | 적용   |
| PR 필수 (직접 푸시 금지) | 적용          | 적용   |
| 허용 병합 방식           | squash, merge | merge  |
| 필수 승인 수             | 0             | 0      |

CI 워크플로를 추가한 뒤에는 두 룰셋에 필수 상태 검사를 등록한다.

## 3. 데이터 구조

### 3.1 다이어그램

여러 개의 독립적인 다이어그램을 관리한다.

편집기 헤더에는 현재 흐름 이름을 표시한다. 이름을 클릭하면 같은 자리에서 편집하고, Enter 또는 포커스 이동으로 저장하거나 Esc로 취소할 수 있다.

각 다이어그램은 다음 속성을 가진다.

- 고유 ID
- 이름
- 설명(선택)
- 생성 및 수정 시각
- 데이터 스키마 버전
- 노드 목록
- 연결선 목록
- 그룹 목록
- 사용자 지정 금융사 목록
- 뷰포트 정보

예시:

- 기본 월간 자금 흐름
- 2026년 12월
- 2027년 1월

다이어그램 생성, 이름 변경, 복제, 삭제를 지원한다.

### 3.2 노드 유형

다음 네 가지 노드 유형을 지원한다.

#### Income — 수입

급여 및 기타 수입의 출처를 표현한다.

- 이름
- 지급처 또는 금융사(선택)
- 사용자 지정 위치

수입 금액과 입금 계좌는 연결선으로 표현한다. 노드에 별도 속성으로 두지 않는다.

#### Account — 계좌

은행, 증권, 연금 등 금융계좌를 표현한다.

- 금융사
- 계좌 별칭
- 사용자 지정 위치

계좌번호는 필수 정보가 아니며, 초기 버전에서는 별도 계좌번호 필드를 제공하지 않는다.

#### Card — 카드

신용카드 결제 수단을 표현한다.

- 카드사
- 카드 이름
- 사용자 지정 위치

캔버스의 노드 카드는 단색 배경 위에 유형별 Lucide 아이콘과 이름을 한 줄로 표시한다. 노드 너비는 이름 길이에 맞춰 달라지며, 카드 높이는 40px, 모서리 반경은 8px이다. 편집 가능한 캔버스에서는 이름을 눌러 입력칸으로 전환하고, 아이콘을 눌러 유형을 바꿀 수 있다. 금융사와 지출 분류는 상세 화면에서 확인한다.

같은 방향으로 연결선이 두 개 이상이면 카드 왼쪽 아래에는 유입 합계, 오른쪽 아래에는 유출 합계 금액만 같은 줄에 표시한다. 금액 범위는 최솟값과 최댓값을 각각 합산한다. 공유 화면과 이미지에도 같은 합계를 표시한다. 자동 정렬은 합계 줄의 높이까지 포함해 행 간격과 그룹 크기를 계산한다.

#### Expense — 지출

최종 자금 사용처 또는 명목을 표현한다.

예시:

- 보험
- 통신비
- ChatGPT
- 쿠팡
- 생활비
- 관리비
- 대출 상환
- 저축·투자

지출 노드는 분류 속성을 가진다.

| 분류 값       | 의미                    |
| ------------- | ----------------------- |
| `consumption` | 일반 소비 지출 (기본값) |
| `saving`      | 저축·투자               |
| `loan`        | 대출 상환               |

분류는 시각적 구분과 월간 요약 지표 집계에 사용한다.

저축·투자를 표현하는 방법은 다음 기준을 따른다.

- 이후 흐름을 이어서 그릴 금융계좌(예: 증권 계좌에서 다시 이체)는 계좌 노드로 만든다.
- 흐름의 끝으로만 표시할 명목은 `saving` 분류의 지출 노드로 만든다.

### 3.3 노드 공통 속성

- ID
- 유형
- 이름
- 좌표
- 금융사 식별자(선택)
- 그룹 ID(선택)

금액은 노드가 아니라 연결선에 저장한다.

### 3.4 좌표 저장 기준

저장 스키마의 노드 좌표는 그룹 소속과 관계없이 **캔버스 절대 좌표**로 저장한다.

React Flow가 요구하는 그룹 기준 상대 좌표는 화면에 넘길 때와 화면에서 받을 때만 변환한다.
변환은 순수 함수로 분리한다.

이 기준에 따라 그룹 편입·해제, JSON 내보내기, 공유, 이미지 내보내기가 좌표 변환 없이 같은 데이터를 사용한다.

### 3.5 사용자 지정 금융사

목록에 없는 금융사는 다이어그램 단위로 저장한다.

- 식별자
- 이름
- 색상

다이어그램을 복제하거나 JSON으로 내보낼 때 함께 포함한다.

## 4. 그룹 기능

### 4.1 목적

기존 구글 슬라이드처럼 특정 사용자가 관리하거나 사용하는 계좌·카드·지출 항목을 배경 영역으로 구분한다.

예시:

- 개인 A
- 개인 B
- 공동 자금

편집 캔버스에서 그룹 이름을 누르면 바로 수정할 수 있다. Enter 또는 포커스 이동으로 저장하고 Esc로 취소한다. 그룹 이름은 자유롭게 변경할 수 있으며 그룹 개수도 제한하지 않는다.

### 4.2 그룹 표현

그룹은 다이어그램의 배경 영역으로 표시한다.

- 그룹 이름
- 배경색
- 테두리
- 위치
- 너비와 높이

그룹 내부에 일반 노드를 배치할 수 있다.

그룹 배경은 반투명하게 표현하여 노드와 연결선이 잘 보이도록 한다.

그룹 색상은 금융사 브랜드 컬러와 독립적으로 관리한다.

### 4.3 그룹 편집

다음 기능을 지원한다.

- 그룹 생성
- 그룹 이름 변경
- 그룹 이동
- 그룹 크기 조절
- 그룹 배경색 변경
- 노드를 그룹에 추가
- 노드를 그룹 밖으로 이동
- 그룹 삭제

#### 소속 판정

노드의 그룹 소속은 **노드 중심점이 그룹 영역 안에 있는지**로 판정하고, 결과를 노드의 그룹 ID에 저장한다.

소속은 다음 시점에만 다시 계산한다.

| 시점                | 다시 계산하는 대상                             |
| ------------------- | ---------------------------------------------- |
| 노드 생성           | 새 노드의 중심점을 포함하는 그룹               |
| 노드 드래그 종료    | 드래그한 노드                                  |
| 그룹 생성           | 새 그룹 영역 안의 노드                         |
| 그룹 크기 조절 종료 | 해당 그룹에 속해 있던 노드와 새 영역 안의 노드 |

그룹을 이동할 때는 소속을 다시 계산하지 않는다.
그룹을 다른 노드 위로 옮겨도 그 노드를 편입하지 않는다.

여러 그룹 영역이 겹치는 위치에서는 가장 나중에 생성한 그룹에 편입한다.

#### 이동과 삭제

그룹 이동 시 내부 노드가 함께 이동해야 한다.

그룹을 삭제하면 그룹만 제거하고, 내부 노드는 삭제하지 않으며 기존 화면 위치를 유지한다.
그룹 해제와 그룹 삭제는 같은 동작이다.

내부 노드까지 지우려면 그룹과 노드를 함께 선택해 삭제한다.

그룹에 노드를 편입하거나 제외할 때도 화면상 위치가 갑자기 바뀌지 않아야 한다.

### 4.4 그룹과 연결선

그룹은 자금 이동의 출발점이나 도착점이 아니다.

연결선은 항상 실제 수입·계좌·카드·지출 노드 사이에 생성한다.

서로 다른 그룹에 속한 노드 사이에도 연결선을 생성할 수 있다.

그룹 경계를 통과하는 연결선은 끊김 없이 표시되어야 한다.

### 4.5 기존 흐름 호환

IndexedDB 버전 2로 업그레이드할 때 기존 노드의 소유자 값을 제거한다. 이전 형식의 JSON과 공유 링크에서도 이 값을 제외하고 읽는다.

### 4.6 구현

React Flow의 Parent Node 기능을 우선 활용한다.

- 그룹 노드는 배경 레이어로 렌더링
- 일반 노드에 `parentId` 지정
- 저장 스키마의 절대 좌표와 React Flow의 상대 좌표 변환 처리 (3.4 참고)
- 그룹 크기 변경 지원
- 그룹 간 연결선 허용

그룹 중첩은 초기 버전에서 지원하지 않는다.

## 5. 자금 흐름 연결선

### 5.1 연결선 데이터

각 연결선은 다음 정보를 가진다.

- ID
- 출발 노드 ID
- 도착 노드 ID
- 최소 금액
- 최대 금액
- 명목 또는 메모(선택)

모든 금액은 원화(KRW) 정수로 저장한다.

### 5.2 연결 규칙

노드 유형에 따라 연결할 수 있는 방향을 제한한다.

| 노드 유형 | 출발점 | 도착점 |
| --------- | ------ | ------ |
| 수입      | 가능   | 불가   |
| 계좌      | 가능   | 가능   |
| 카드      | 가능   | 가능   |
| 지출      | 불가   | 가능   |

추가 규칙:

- 자기 자신으로 향하는 연결은 만들 수 없다.
- 같은 출발·도착 쌍에는 같은 방향의 연결선을 하나만 만든다. 명목이 여럿이면 지출 노드를 나누어 표현한다.
- 반대 방향의 연결선은 따로 만들 수 있다. (예: A → B와 B → A)
- 순환 흐름은 허용한다.

허용하지 않는 연결을 시도하면 연결선을 만들지 않고, 연결 대상이 될 수 없는 노드는 드래그 중에 구분해서 보여 준다.

노드에는 연결용 출발점과 도착점을 유형에 따라 각각 한 개까지 표시한다. 연결점은 평소에 숨긴다. 포인터를 올리거나 키보드로 노드에 포커스하면 출발 연결점이 나타나고, 연결을 시작하면 연결할 수 있는 노드의 도착 연결점이 표시된다.

연결 가능 여부 판정은 순수 함수로 분리한다.

### 5.3 금액 규칙

모든 금액은 **월 기준**이다.

연납·분기납처럼 월 단위가 아닌 항목은 월 환산 금액으로 입력하고, 필요하면 메모에 실제 납부 주기를 적는다.

고정 금액은 최소와 최대를 동일하게 지정한다.

예시:

| 최소    | 최대    | 의미                     |
| ------- | ------- | ------------------------ |
| 32,000  | 32,000  | 고정 금액                |
| 500,000 | 800,000 | 범위 금액                |
| 0       | 200,000 | 없을 수도 있는 범위 금액 |

금액 입력 시 다음을 검증한다.

- 음수 금액 금지
- 최소 금액은 최대 금액 이하
- 원 단위 정수만 허용
- 값이 비어 있는 경우 저장 불가
- 0원 허용

### 5.4 연결선 두께

연결선 두께는 금액을 로그 계열 스케일로 변환하여 계산한다.

0원부터 `scaleSymlog().constant(100000)`을 적용한다. 양수 금액 x의 변환은 `log1p(x / 100000)`에 해당한다.

기본 설정:

- 최소 두께: 2px
- 최대 두께: 14px
- 기본 계산 금액: 최소·최대의 중간값
- 금액에 따른 두께 자동 갱신

#### 스케일 기준

스케일 도메인은 다이어그램 내용과 무관한 **고정 절대 범위**로 한다.

- 도메인: 0원 ~ 10,000,000원
- 10,000,000원을 넘는 금액은 최대 두께로 고정한다.

이 기준에 따라 같은 금액은 어느 다이어그램에서나 같은 두께가 되고, 한 연결선의 금액을 바꿔도 다른 연결선의 두께는 변하지 않는다.

도메인 값과 두께 범위는 한 곳의 상수로 관리한다.

로그 스케일은 정확한 금액 비율을 의미하지 않으므로 실제 금액은 별도로 표시한다.

### 5.5 연결선 렌더링

- 기본적으로 부드러운 곡선 사용
- 노드 이동 시 경로 자동 갱신
- 연결선 선택 가능
- 연결선 선택 시 강조 표시
- 노드와 연결선이 겹쳐도 레이블 가독성 확보
- 여러 연결선이 같은 노드에 연결될 수 있음

#### 연결 지점(Handle)

- 도착 지점은 노드 왼쪽, 출발 지점은 노드 오른쪽에 고정한다.
- 출발·도착 포트는 카드의 오른쪽과 왼쪽 바깥에 표시한다. 출발 포트는 카드나 카드 바깥의 포트 위치에 마우스를 올리면 나타난다. 연결이 완료된 선은 카드 가장자리에서 시작하고 끝난다.
- 한 노드에 여러 연결선이 붙으면 표시용 포트의 수와 관계없이, 상대 노드의 세로 위치 순서대로 각 연결선의 끝점을 나누어 배치한다.

연결 지점은 세로 순번 i(0부터 시작)와 연결 수 n에 대해 높이의 (i+0.5)/n에 둔다. 캔버스와 이미지 내보내기는 같은 위치 비율, 곡선과 화살촉 계산 함수를 쓴다. 도착 노드 앞에 선 두께와 연결 거리, 인접 포트 간격을 고려한 화살촉을 표시한다.

### 5.6 금액 레이블

각 연결선에 금액을 표시한다. 레이블에는 "원"을 붙이지 않는다. 편집 화면에서 금액 레이블을 누르면 원 단위 정수 또는 최소~최대 범위를 제자리에서 입력할 수 있다.

표기 규칙:

| 조건                                      | 표기                       | 예시                        |
| ----------------------------------------- | -------------------------- | --------------------------- |
| 만 원 단위로 나누어떨어짐                 | `N만`                      | 500,000 → `50만`            |
| 1억 원 이상이고 만 원 단위로 나누어떨어짐 | `N억` 또는 `N억 M만`       | 120,000,000 → `1억 2,000만` |
| 그 외                                     | 원 단위 전체, 천 단위 쉼표 | 32,000 → `32,000`           |

범위 금액:

| 조건                                                | 표기                                    | 예시                         |
| --------------------------------------------------- | --------------------------------------- | ---------------------------- |
| 한쪽이 1억 원 이상                                  | 양 끝을 고정 금액 규칙에 따라 각각 표기 | `1억~2억`, `1만~1억 2,000만` |
| 양쪽 모두 1억 미만이고 만 원 단위                   | 단위를 한 번만 표기                     | `50~80만`, `0~20만`          |
| 양쪽 모두 1억 미만이고 한쪽이라도 만 원 단위가 아님 | 양쪽 모두 원 단위 전체                  | `32,000~45,500`              |

정확한 원 단위 금액은 연결선을 선택했을 때의 속성 패널과 툴팁에서 `500,000원` 형식으로 확인할 수 있어야 한다.

금액 레이블은 배경 없이 표시하고 글자에 밝은 외곽선을 적용해 연결선 위에서도 읽을 수 있도록 한다.

금액 표기 함수는 순수 함수로 분리한다.

## 6. 금융사 브랜드 컬러

### 6.1 기본 정책

금융사별 브랜드 컬러를 사전에 정의한다.

랜덤 색상은 사용하지 않는다.

노드는 금융사에 연결된 브랜드 컬러를 자동으로 적용한다.

금융사 로고는 사용하지 않는다. 금융사는 이름과 색상으로만 표현한다.

초기 지원 대상은 다음과 같다.

| 구분 | 금융사                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------- |
| 은행 | 카카오뱅크, KB국민은행, 신한은행, 하나은행, 우리은행, NH농협은행, IBK기업은행, 토스뱅크, 케이뱅크 |
| 증권 | 미래에셋증권, 한국투자증권, NH투자증권, 삼성증권, KB증권, 키움증권, 토스증권                      |
| 카드 | 신한카드, 삼성카드, 현대카드, KB국민카드, 롯데카드, 우리카드, 하나카드, BC카드, NH농협카드        |

브랜드 컬러는 공식 브랜드 가이드를 확인하여 적용한다.

공식 가이드에서 색상값을 확인할 수 없으면 금융사의 공식 웹사이트 또는 해당 금융사가 직접 배포한 디지털 자료의 대표색을 근사값으로 적용하고 출처를 남긴다. 자료와 대조하지 못한 값은 잠정값으로 표시한다.
레지스트리의 각 항목에 색상의 출처(공식 가이드 또는 근사값)를 주석으로 남긴다.

브랜드 정보는 별도 레지스트리로 관리하여 확장할 수 있도록 한다.

### 6.2 색상 적용

- 노드 배경: 브랜드 컬러를 활용한 연한 톤
- 노드 테두리: 브랜드 기본색
- 연결선: 기본적으로 출발 금융사의 브랜드 컬러
- 일반 지출: 중립적인 색상
- 그룹: 사용자 지정 배경색

연결선이 금융사와 연결되지 않는 경우 적절한 중립색을 사용한다.

브랜드 색상과 무관하게 텍스트의 명도 대비를 확보해야 한다.

#### 밝은 브랜드 컬러 보정

카카오뱅크의 노란색처럼 밝은 색은 밝은 캔버스에서 연결선과 테두리가 잘 보이지 않는다.

- 캔버스 배경색 대비 명도 대비가 3:1에 미치지 못하는 브랜드 컬러는 연결선과 테두리에 어둡게 보정한 색을 사용한다.
- 보정색은 레지스트리에서 금융사별로 지정할 수 있고, 지정하지 않으면 기본색에서 계산한다.
- 노드 배경은 기본색에서 연한 톤을 만든다. 카카오뱅크는 밝은 캔버스에서 구분되도록 더 진한 노란색을 카드 배경에 적용한다.

대비 계산과 보정색 계산은 순수 함수로 분리한다.

### 6.3 브랜드 선택

새 계좌와 카드는 중립색의 금융사 미지정 상태로 생성한다. 속성에서 금융사를 선택하거나 선택을 해제할 수 있다. 유형을 바꿀 때 기존 선택을 보존하며, 지출 유형에서는 금융사 대신 지출 분류를 표시한다.

검색 가능한 금융사 목록을 제공한다.

목록에 없는 금융사는 사용자 지정 이름과 색상으로 등록할 수 있다. 등록한 금융사는 해당 다이어그램에 저장한다. (3.5 참고)

## 7. 비주얼 편집기

### 7.1 화면 구성

기본 화면은 세 영역으로 구성한다.

**왼쪽 도구 패널**

- 수입 노드 추가
- 계좌 노드 추가
- 카드 노드 추가
- 지출 노드 추가
- 그룹 추가

**중앙 캔버스**

- 다이어그램 표시
- 노드 자유 배치
- 연결선 생성
- 그룹 편집
- 확대·축소 및 이동

**오른쪽 속성 패널**

선택한 객체에 따라 편집 항목을 변경한다.

노드 선택:

- 이름
- 유형
- 금융사
- 분류 (지출 노드만)
- 유입·유출 합계 (8장 참고)

연결선 선택:

- 최소 금액
- 최대 금액
- 명목 및 메모

그룹 선택:

- 이름
- 배경색

### 7.2 기본 편집 동작

- 노드 드래그
- 노드 간 연결 생성
- 노드 및 연결선 삭제
- 그룹 드래그
- 그룹 크기 변경
- 여러 객체 선택
- 선택 객체 함께 이동
- Undo / Redo
- Delete 또는 Backspace로 선택 객체 삭제

텍스트를 입력하는 동안에는 편집기 단축키가 입력을 방해하지 않아야 한다.

출발 노드의 속성 패널에서 **연결할 노드**를 선택하고 **연결 추가**를 누를 수 있다. 드래그 연결과 같은 규칙을 적용한다.

### 7.3 Undo / Redo

이력에 기록하는 단위는 다음과 같다.

| 동작                       | 기록 단위                                             |
| -------------------------- | ----------------------------------------------------- |
| 방향키 이동                | 한 번의 이동 입력당 한 단계. 키 반복 입력도 각각 기록 |
| 노드·그룹 드래그           | 드래그 종료 시 1단계                                  |
| 그룹 크기 조절             | 조절 종료 시 1단계                                    |
| 텍스트·금액 입력           | 입력 확정(포커스 이탈 또는 Enter) 시 1단계            |
| 생성, 삭제, 연결           | 동작마다 1단계                                        |
| 여러 객체를 함께 이동·삭제 | 묶어서 1단계                                          |

- 뷰포트(확대·축소, 화면 이동)와 선택 상태는 이력에 기록하지 않는다.
- 이력은 다이어그램별로 관리하고, 다른 다이어그램을 열면 초기화한다.
- 이력은 저장하지 않는다. 브라우저를 다시 열면 이력은 비어 있다.

### 7.4 캔버스

- 마우스 휠 확대·축소
- 빈 공간 드래그로 화면 이동
- 전체 화면 맞춤(Fit View)
- 현재 확대 비율 표시
- 적절한 크기의 배경 격자
- 필요하면 격자 표시 전환

초기 노드 배치는 좌에서 우로 자금이 흐르는 형태를 권장한다.

노드는 자유롭게 이동할 수 있다. 편집 화면에서 자동 정렬을 누르면 연결 방향을 기준으로 노드를 왼쪽에서 오른쪽으로 배치하고, 같은 단계의 노드와 그룹은 정렬 전의 위아래 순서를 유지하며, 단계별 노드 묶음의 세로 중심을 맞춘다. 같은 그룹 안이나 그룹 밖에서 단일 부모를 가진 노드가 여러 갈래로 이어지면, 하위 묶음의 세로 중심을 부모에 맞추고 다음 형제는 앞 가지의 전체 높이 아래에 배치한다. 연결선과 금액을 읽을 수 있는 간격을 둔다. 그룹 소속을 유지한다. 순환 연결에서는 일부 연결이 왼쪽으로 향할 수 있다. 자동 정렬은 현재 확대 비율을 유지하고, 상단 요약이 노드를 가릴 때 화면을 세로로 이동한다. 확대 컨트롤의 100% 버튼으로 원래 배율을 선택할 수 있다. 정렬 전체를 한 번에 실행 취소할 수 있다.

편집 화면에서 선택한 노드를 Ctrl/⌘+C로 복사하고 Ctrl/⌘+V로 붙여넣을 수 있다. 속성 패널의 복사 버튼과 왼쪽 사이드바의 붙여넣기 버튼으로도 같은 작업을 할 수 있다. 같은 탭에서 다른 다이어그램으로 옮길 수 있다. 여러 노드를 복사하면 그 노드들 사이의 연결도 포함된다. 붙여넣은 노드는 현재 캔버스 가운데에 배치되며, 그룹 소속은 새 위치를 기준으로 정한다. 한 번의 실행 취소로 붙여넣기를 되돌린다.

사용자가 설정한 좌표를 우선한다.

### 7.5 시각적 우선순위

화면에서 가장 먼저 알아볼 수 있어야 하는 정보는 다음 순서다.

1. 어느 계좌에서 어느 계좌로 돈이 이동하는가
2. 이동하는 금액의 규모는 어느 정도인가
3. 어떤 사용자의 자금 영역인가
4. 최종적으로 어떤 명목의 지출인가

노드와 연결선은 장식보다 가독성을 우선한다.

## 8. 자금 흐름 합계

편집 캔버스는 편집 영역의 가장자리까지 펼쳐진다. 캔버스 상단에 띄운 요약은 월 수입(수입 노드의 유출), 월 소비 지출(일반 소비 노드의 유입), 월 저축·투자(저축·투자 노드의 유입)를 표시한다. 대출 상환 노드가 있으면 해당 노드로 들어가는 금액을 **월 대출 상환**으로 별도 표시한다. 각 지표에서 연결선의 최소값과 최대값을 따로 합산한다. 계좌 간 이체는 지출로 중복 집계하지 않는다.

각 노드의 연결선 금액을 기준으로 다음 값을 계산한다.

- 유입 최소 합계
- 유입 최대 합계
- 유출 최소 합계
- 유출 최대 합계

사용자가 노드를 선택하면 속성 패널에서 확인할 수 있다.

다만 유입·유출 금액이 일치하지 않는다고 오류로 처리하지 않는다.

Money Flow는 실제 회계 장부가 아니라 계획 흐름도이므로 일부 금액이 생략되거나 예상 범위가 다를 수 있다.

초기 버전에서 실제 계좌 잔액이나 월말 잔액은 계산하지 않는다.

## 9. 저장 기능

### 9.1 로컬 저장

IndexedDB를 이용하여 데이터를 저장한다.

- 변경 사항 자동 저장
- 여러 다이어그램 관리
- 마지막 작업 다이어그램 복원
- 노드 위치와 그룹 위치 보존
- 캔버스 뷰포트 보존

자동 저장은 변경 사항을 짧은 시간 동안 모아서 처리하는 디바운스 방식을 사용한다.

저장 실패 시 사용자에게 알린다.

### 9.2 다이어그램 관리

다음 기능을 제공한다.

- 새 다이어그램
- 이름 변경
- 복제
- 삭제
- 기존 다이어그램 열기

삭제 시 확인 절차를 제공한다.

### 9.3 JSON 가져오기·내보내기

다이어그램을 JSON 파일로 내보낼 수 있어야 한다.

JSON에는 다음 정보를 포함한다.

- 데이터 스키마 버전
- 노드 및 연결선
- 그룹
- 사용자 지정 금융사
- 레이아웃
- 뷰포트

가져오기 시 스키마를 검증한다.

기존 데이터와 ID가 충돌하지 않도록 새 다이어그램으로 가져온다.

지원하지 않는 버전이나 손상된 파일은 명확한 오류 메시지를 표시한다.

### 9.4 데이터 보호

구글 슬라이드를 대체하면 브라우저의 IndexedDB가 유일한 원본이 된다.
브라우저 정책이나 사용자의 사이트 데이터 삭제로 지워질 수 있으므로 다음을 적용한다.

#### 영구 저장 요청

- 첫 다이어그램을 저장할 때 `navigator.storage.persist()`로 영구 저장을 요청한다.
- 요청이 거부되어도 동작에는 영향을 주지 않는다.

#### 백업 안내

- 다이어그램 목록 화면에 "데이터는 이 브라우저에만 저장되며, JSON 내보내기로 백업할 수 있다"는 안내를 표시한다.

#### 여러 탭에서의 동시 편집

- 같은 다이어그램이 다른 탭에서 수정되면 이를 감지해 사용자에게 알린다.
- 사용자는 최신 내용 다시 불러오기 또는 현재 탭 내용으로 계속하기를 선택한다.
- 알림 없이 다른 탭의 변경을 덮어쓰지 않는다.
- 탭 간 실시간 병합은 지원하지 않는다.

#### 스키마 마이그레이션

- 저장 데이터와 JSON 파일, 공유 데이터는 같은 스키마 버전 체계를 사용한다.
- 스키마가 바뀌면 이전 버전에서 다음 버전으로 변환하는 함수를 버전마다 하나씩 추가하고, 순서대로 적용한다.
- 현재 앱보다 높은 버전의 데이터는 열지 않고 오류 메시지를 표시한다.
- 마이그레이션 함수는 순수 함수로 작성하고 테스트한다.
- 스키마 2는 계좌·카드의 금융사 미지정을 허용한다. 스키마 1의 기존 금융사 선택은 그대로 보존한다.

## 10. 공유 기능

### 10.1 URL 공유

다이어그램 데이터를 압축하여 URL에 포함한다.

- 백엔드 없음
- 로그인 없음
- 공유 링크 생성
- 링크 복사
- 공유 데이터 검증
- 읽기 전용 화면 제공

URL에는 다이어그램을 재현하는 데 필요한 데이터만 포함한다.

압축된 URL 데이터는 암호화된 정보가 아니므로 링크를 가진 사람이 내용을 확인할 수 있다는 점을 공유 화면에서 명확하게 안내한다.

### 10.2 URL 형식

공유 데이터는 URL의 **해시(`#`) 부분**에 넣는다. 해시는 서버로 전송되지 않으므로 호스팅 서버의 접근 기록에 남지 않는다.

```text
https://<호스트>/#share=<형식 버전>.<데이터>
```

- 형식 버전: 공유 URL 인코딩 방식의 버전. 다이어그램 스키마 버전과 별개로 관리한다.
- 데이터: 다이어그램 JSON을 UTF-8로 직렬화하고 압축한 뒤 base64url로 인코딩한 문자열

| 형식 버전 | 압축          | 내용                                                             |
| --------- | ------------- | ---------------------------------------------------------------- |
| 1         | gzip          | 다이어그램의 ID와 좌표를 그대로 담는다. 열기만 지원한다.         |
| 2         | `deflate-raw` | ID를 목록 안의 순번으로 바꾸고 좌표와 그룹 크기를 정수로 맞춘다. |

새 링크는 형식 버전 2로 만든다. 무작위 ID는 압축되지 않아 주소 길이의 대부분을 차지하므로, 노드·연결선·그룹·사용자 지정 금융사의 ID를 각 목록의 순번(36진수)으로 바꾼다. 기본 제공 금융사의 식별자는 그대로 둔다.

- 이름, 금액, 메모, 그룹 소속, 연결 관계는 그대로 보존한다.
- 좌표와 그룹 크기는 1px 단위로 반올림한다.
- 수신자가 복사한 다이어그램은 순번 ID를 그대로 사용한다. ID는 다이어그램 안에서만 고유하면 된다.
- 형식 버전 1로 이미 만든 링크는 계속 열 수 있다.

URL 전체 길이가 **8,000자**를 넘으면 공유 링크를 만들지 않고 JSON 파일 공유를 안내한다. **[확정 필요]**
데이터를 임의로 일부 제거하지 않는다.

8,000자는 보수적으로 잡은 기본값이다. 실제로 링크를 전달할 메신저에서 확인한 결과에 따라 조정한다.

인코딩과 디코딩은 순수 함수로 분리한다.

### 10.3 공유 화면

공유 링크로 열면 항상 **읽기 전용 화면**을 보여 준다.

- 다이어그램 조회
- 확대·축소 및 화면 이동
- 노드 및 연결선 정보 확인
- 편집 불가
- "내 다이어그램으로 복사" 버튼

복사한 다이어그램은 새 ID로 로컬에 저장하며 독립적으로 편집할 수 있다. 원본과 동기화하지 않는다.

읽기 전용 모드는 UI 동작 제한이며 보안 접근 제어 기능이 아니다.
링크를 가진 사람은 누구나 내용을 복사할 수 있으므로 "복사 허용 여부"를 별도 모드로 두지 않는다.

잘못되었거나 지원하지 않는 공유 데이터는 명확한 오류 메시지를 표시한다.

### 10.4 개인정보

초기 버전에서는 계좌번호, 주민등록번호 등 민감한 식별정보를 별도 데이터 필드로 관리하지 않는다.

공유 링크를 만들기 전에 포함될 노드 이름과 금액을 확인할 수 있도록 한다.

공유 링크를 열었다고 기존 로컬 데이터가 자동으로 덮어써져서는 안 된다.
공유 화면은 사용자가 "내 다이어그램으로 복사"를 누르기 전까지 로컬 저장소에 아무것도 쓰지 않는다.

## 11. 이미지 내보내기

현재 다이어그램을 다음 형식으로 내보낼 수 있어야 한다.

- SVG
- PNG

다음 요소를 모두 포함한다.

- 노드
- 연결선
- 금액 레이블
- 그룹 배경과 그룹 이름
- 금융사 브랜드 컬러

편집 UI, 선택 테두리, 연결 핸들, 도구 패널은 이미지에 포함하지 않는다.

내보내기 범위는 전체 다이어그램으로 한다.

현재 화면의 확대 비율에 관계없이 결과물이 잘리지 않아야 한다.

### 11.1 SVG

화면 DOM을 캡처하지 않고, 다이어그램 데이터에서 SVG를 **직접 생성**한다.

- 사각형, 경로, 텍스트 등 순수 SVG 요소만 사용한다.
- HTML을 감싸는 `foreignObject`는 사용하지 않는다. 디자인 도구와 일반 이미지 뷰어에서 열 수 있어야 한다.
- 글꼴은 파일에 포함하지 않고 시스템 글꼴 목록을 지정한다.
- 노드 크기는 화면에서 측정한 값을 입력으로 받는다. 이름에 맞춘 너비, 브랜드 배경 톤과 유형 아이콘은 화면과 같은 SVG 카드로 그린다.
- 연결선 경로, 두께, 금액 레이블, 색상은 화면 렌더링과 같은 순수 함수를 사용한다.

SVG 생성 함수는 다이어그램 데이터와 노드 크기를 받아 SVG 문자열을 반환하는 순수 함수로 작성한다.

### 11.2 PNG

11.1에서 만든 SVG를 브라우저에서 래스터화하여 PNG로 만든다. 화면과 SVG, PNG가 같은 렌더링 경로를 사용한다.

- 해상도: 2배율
- 배경: 흰색
- 여백: 다이어그램 바깥쪽 40px

SVG에도 같은 여백을 적용한다. SVG 배경은 흰색으로 채운다.

- `lib/storage/` — IndexedDB, 스키마 마이그레이션
- `lib/brands/` — 금융사 브랜드 레지스트리
- `types/` — 공통 데이터 타입과 스키마

실제 구조는 기능 규모와 기존 저장소 상태를 고려하여 조정한다.

단일 폴더에 지나치게 많은 파일을 집중시키지 않는다.

## 14. 테스트

테스트는 두 계층으로 나눈다.

| 계층          | 도구                  | 대상                                                |
| ------------- | --------------------- | --------------------------------------------------- |
| 단위 테스트   | Vitest                | 순수 함수와 상태 저장소(store) 로직                 |
| 스모크 테스트 | Playwright (Chromium) | 실제 브라우저가 필요한 편집·저장·공유·내보내기 흐름 |

드래그, 렌더링, 파일 저장처럼 실제 브라우저가 필요한 동작은 단위 테스트로 검증했다고 보고하지 않는다.

### 14.1 단위 테스트 (Vitest)

데이터:

- 최소·최대 금액 검증
- 연결 규칙 판정
- 금액 합계 계산
- 로그 스케일 변환과 도메인 초과 처리
- 금액 표기
- JSON 직렬화 및 복원
- 데이터 스키마 검증과 마이그레이션

편집 로직 (상태 저장소):

- 노드 추가·삭제
- 연결선 추가·삭제
- 그룹 생성·삭제
- 그룹 이동 시 내부 노드의 절대 좌표 갱신
- 그룹 편입·해제 시 좌표 유지
- 소속 판정
- Undo / Redo 기록 단위

저장 및 공유:

- 다이어그램 복제
- 공유 URL 인코딩·디코딩
- 잘못된 공유 데이터 처리
- 길이 기준 초과 처리

내보내기:

- SVG 문자열에 모든 노드·연결선·그룹·금액 레이블이 포함되는지
- SVG 영역이 전체 다이어그램과 여백을 포함하는지
- `foreignObject`가 없는지

브랜드:

- 명도 대비 계산과 보정색 적용

### 14.2 스모크 테스트 (Playwright)

17장의 최종 완료 시나리오 중 핵심 흐름을 하나의 시나리오로 검증한다.

- 노드를 추가하고 드래그로 연결선을 만든다.
- 금액을 입력하면 연결선 두께가 달라진다.
- 그룹을 만들고 노드를 넣은 뒤 그룹을 이동하면 노드가 함께 이동한다.
- 서로 다른 그룹의 노드를 잇는 연결선이 표시된다.
- 새로 고침 후 작업 내용이 복원된다.
- 공유 링크를 열면 읽기 전용 화면이 표시되고, 로컬 다이어그램 목록이 바뀌지 않는다.
- SVG와 PNG 파일이 내려받아지고, PNG의 크기가 0이 아니다.

스모크 테스트는 Chromium 하나로 실행한다. 다른 브라우저 검증은 후속 과제로 분리한다.

### 14.3 수동 검증

다음 항목은 자동화하지 않고, 해당 기능의 PR에서 수동 확인 결과를 보고한다.

- 내보낸 SVG를 외부 디자인 도구에서 열었을 때의 모습
- 모바일 화면에서의 조회
- 금융사 색상과 텍스트의 가독성

### Phase 1 — 기본 프로젝트와 데이터 모델

### Phase 2 — 비주얼 편집기

- 노드 생성·수정·삭제
- 자유 배치

- 다이어그램 목록

**완료 조건:** 브라우저를 닫았다 다시 열어도 이전 작업을 이어갈 수 있다.

### Phase 4 — 그룹

- 그룹 노드

- 노드 그룹 편입·해제
- 그룹 간 연결선
- 그룹별 배경색

**완료 조건:** 개인 A·개인 B·공동 자금 영역을 자유롭게 구성할 수 있다.

### Phase 5 — 공유 및 이미지 출력

- 내 다이어그램으로 복사
- SVG·PNG 내보내기

**완료 조건:** 작성한 흐름도를 다른 사람에게 전달하고 이미지로 저장할 수 있다.

### Phase 6 — 마무리

## 16. AI 작업 지침

공통 작업 원칙, Git·PR 규칙은 저장소의 `AGENTS.md`를 따른다. 여기에는 이 프로젝트에만 해당하는 지침을 적는다.

1. 구현은 15장의 Phase 순서대로 진행하되 기능 단위로 검증한다.
2. TypeScript 타입을 명확하게 정의하고 불필요한 `any` 사용을 피한다.
3. 단순한 계산과 데이터 검증은 순수 함수로 분리한다.
4. UI 렌더링과 금융 흐름 계산 로직을 분리한다.
5. 저장 데이터의 스키마 버전을 관리한다.
6. 불필요한 추상화와 범용 다이어그램 기능을 추가하지 않는다.
7. 이 명세와 다르게 구현해야 하는 경우, 이유를 PR에 적고 명세 문서를 함께 갱신한다.

## 17. 최종 완료 기준

다음 시나리오를 코드 수정 없이 웹 UI에서 수행할 수 있어야 한다.

1. 새 다이어그램을 생성한다.
2. 급여 A와 급여 B를 수입 노드로 추가한다.
3. 두 급여가 모이는 카카오뱅크 계좌를 추가한다.
4. 다른 금융사 계좌와 신용카드 노드를 추가한다.
5. 계좌와 카드를 연결하고 최소·최대 이체 금액을 입력한다.
6. 카드별 통신비·구독료·생활비 등 지출 항목을 연결한다.
7. 금액 규모에 따라 연결선 두께가 자동으로 달라지는지 확인한다.
8. 개인 A·개인 B·공동 자금 그룹을 생성한다.
9. 계좌와 카드를 해당 그룹에 배치하고 그룹을 이동한다.
10. 작업 내용을 저장하고 브라우저를 다시 열어 복원한다.
11. 다이어그램을 복제하거나 JSON으로 내보낸다.
12. 공유 URL을 생성하여 읽기 전용으로 확인한다.
13. 전체 다이어그램을 SVG와 PNG로 출력한다.

**최종 목표: 기존 구글 슬라이드 자금 흐름도를 Money Flow에서 완전히 재현하고, 이후 금액과 연결 관계를 편리하게 유지·관리할 수 있는 상태.**
